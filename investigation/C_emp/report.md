## 2. 实验2：白块像素 → 碎块身份映射

方法：页内用 mesh.matrixWorld × centroid 投到屏幕，白像素做 8 邻域连通域，按质心归属最近碎片。

### p=0.9 稳态（sim=6.2）碎片状态实况
- **band0/1/2 全部 stored=0、u_cool=0**（撞击只指派 band3，代码 L2083）。
- band3：88 片 stored 合计 252（均≈2.9），max stored=5 → u_cool max=0.45。
- shellInnerAlpha=0.212（展开后基准面已淡出但未消失）。

### 白像素按 band / cool 归属（p=0.9）
| band | 白像素 | 占比 |
|---|---|---|
| band0（内） | 267 | 7% |
| band1 | 701 | 19% |
| band2 | 1118 | 31% |
| band3（外） | 1511 | 42% |

- **落在 u_cool=0 碎片上的白像素 = 2086 / 3597 = 58.0%**；u_cool>0 仅 42%。
- 最白碎片 TOP：**#13 band2 stored=0 u_cool=0 → 296px**；**#8 band1 stored=0 u_cool=0 → 273px**。即两片最白的都在**内片、零冷色调**。

### "被打也不发白"的外圈片（用户观察）

→ **用户观察像素层成立**：frag#17 stored/u_cool 双双拉满，屏幕上却是 0 白像素。

- 全部 stored=0（p<0.8 时 _STORED_DRAIN=40/s 已排空），白像素 **100% 在 u_cool=0 片**。

## 3. 实验3：开关矩阵（两 p 值，8 条件）

每条件应用运行时 API → 等 ~3 帧（3.5 真实-s）→ 截图 → 还原。白块%：

| 条件 | p=0.5 白% | p=0.9 白% | 读法 |
|---|---|---|---|
| baseline | 1.017 | 1.601 | |
| facetGain 关 (fac=0) | 0.972 | 1.795 | 两 p 均不降 → **排除 facetGain** |
| **shellInner 关** | **0.026** | **1.395** | **闭合态崩溃(-97%)；展开态几乎不动(-13%)** |
| core 关 | 0.949 | **2.476↑** | 展开态关核后白反而升 → 核不是白源 |
| pulse 关 | 0.571 | 2.134↑ | 闭合态脉冲有贡献；展开态关了反而更亮 |
| 数据流关 (particles+ambient) | 0.659 | 1.776 | 闭合态部分贡献 |
| cool 强制 0（全部 stored=0） | 1.094 | 1.605 | **与 baseline 相同 → cool 不是白源** |
| cool 强制 0.5（全部 stored=6） | 1.256 | 1.740 | 拉满也几乎不增 |

### 关键问题回答
1. **shellInner 关在 p=0.9 下白块是否仍在？** 在。1.60%→1.40%，只少 0.2 个百分点，远非闭合态的崩溃。**基准面只解释闭合态（0.35–0.8）的白，不解释 p>0.8 的白。**
2. **cool 强制 0 后 p=0.9 内片白是否消失？** 不消失。1.601%→1.605%（完全相同）。**stored→u_cool 链路对内片白毫无影响**——内片白是静态因素，不是 stored 驱动。

### 矛盾的解释（用户"35-80 发白肯定不是基准面" vs 上午"关基准面降到 0.09%"）
两者都对，因为是**两个 p 区间、两套不同的白源**：
- **闭合区 p∈[0.35,0.8]**：shellInner（基准面，alpha=0.45）是主发光面。关掉它白块 1.02%→0.026%，与上午 p=0.65 的 1.89%→0.09% 同构。**此区白就是基准面（叠加脉冲/数据流约 0.3–0.4%）。**
- **展开区 p>0.8**：基准面已淡出（alpha=0.21）且后移，露出的是**晶体碎块材质本身**。此时关基准面几乎不减少白。用户在高能态看到的白确实"不是基准面"——他的直觉对应这个区间。
- 上午测的是 p=0.65（闭合），用户断言的是 p>0.8（展开）。**采样 p 不同导致结论相反，不是测量错误。**

截图：`shots/p05_*.png`、`shots/p09_*.png`；数据 `csv/matrix_p09.json`、`csv/matrix_p05.json`、`csv/matrix_summary.csv`。

## 4. 实验4：打片实验（band3 外片 vs 内片）

选取：band3 = frag#144（自然 stored=5/u_cool=0.45，屏位 719,474）；内片 = frag#0（band0，676,329）。逐档强制 stored 并读回 u_cool：

| 强制 stored | 读回 u_cool | b3#144 屏色 RGB | 亮度 |
|---|---|---|---|
| 0（cool0） | 0 | (120,114,129) | ~118 |
| 2 | 0.18 | (111,106,121) | ~111 |
| 4 | 0.36 | (67,57,67) | ~63 |
| 6 | 0.50（封顶） | (93,99,120) | ~100 |

- **stored→u_cool 写回链路机械上是通的**（2→0.18、4→0.36、6→0.50，与 L2841 `min(stored*0.09,0.5)` 吻合）。
- 但即便 u_cool=0.5 封顶，该碎片屏色亮度 ~100、蓝灰，**远低于白阈值（>150）**。shader 里 cool 项是 `c += vec3(0.07,0.12,0.20)*u_cool`（最多 +0.10 蓝）+ `alpha*=1.225`，只加透明度与微蓝，**不产生亮度**。
- **判定：band3 的 stored→u_cool→颜色链路真实生效，但它在物理上无法把任何碎片推到"白"。** 这解释了 frag#17 stored 满却 0 白像素。

**交源码审计的疑点**（对照 L2839-2841 与 L1977-1985）：
- L1266 的冷色辉亮项 `vec3(0.07,0.12,0.20)*u_cool` 幅度太小（u_cool=0.5 时 +0.10 蓝），与"撞击应变白"的预期视觉不匹配——用户以为撞击应变白，但 shader 只给了冷蓝增透。请审计：是否曾有更大的白/亮项被删（注释提到"白块问题由 _STORED_DRAIN 根治，不再靠压低幅度"），当前幅度是否就是"打不白"的直接原因。
- L2841 每帧无条件 `u_cool = stored*0.09`，但内片（band0/1/2）stored 恒 0，故内片白与该链路完全无关——内片白只能来自基准面/核光/晶体基础项。

## 5. 实验5：静态性判定（u_cool 强制 vs facetGain 拉满）

| 状态 | p=0.9 白% |
|---|---|
| baseline | 1.688 |
| fac=0（facetGain 关） | 1.795（矩阵） |
| fac=0.5 | 1.766 |
| fac=2（facetGain 拉满，完整旧幅度） | 1.705 |

- facetGain 从 0 拉到 2，白块% 几乎不动（1.70–1.80%）。
- 结合实验4（u_cool 拉满也不白）：**白块既不是 stored 驱动、也不是 facetGain 静态抖动驱动**。
- 它是**晶体碎片材质本身的基础面亮度 + 视角依赖（fresnel/背面）**，在展开态半透明壳体下叠加核心橙光透缝。p=0.9 旋转45°白块%翻 3 倍（1.66→5.32%）是最强证据：亮的是某些朝向的晶体面，随视角大量现身。

截图：`shots/exp5_baseline.png`、`exp5_fac2.png`、`exp5_fac05.png`。

## 6. 实验6：时序采样（p=0.9，sim 6.75→12.55，约 5.8 sim-s）

8 次采样白块%：`1.72 / 1.91 / 2.18 / 2.01 / 1.58 / 1.73 / 1.89 / 1.78`
- 均值 **1.85%**，范围 1.58–2.18（呼吸/脉冲调制约 ±15%）。
- 空间持续性网格（24×16，# = ≥6/8 次白，+ = 3–5，. = 1–2）：
```
               ######+
             .#########
             +##+######+
             ##++#######
             ##+++#++##+
             .###+++###
               #######
```
- **持续白格(#)=50，间歇(+)=15，纯瞬时脉冲白格(.)=2。**
- 判定：展开态白块 **~80% 是稳态静态白（身份固定的晶体面）**，~20% 随呼吸/脉冲环扫波动；真正"随脉冲闪白"的像素极少（仅 2 格）。

## 7. 候选机制判定总表

| 候选机制 | 实测证据 | 判定 |
|---|---|---|
| 基准面 shellInner 透射 | p=0.5 关→0.026%（崩）；p=0.9 关→1.40%（不动） | **闭合态主因 / 展开态排除** |
| facetGain 静态增益 (fac) | fac=0 不降、fac=2 不增（1.7–1.8%） | **排除** |
| stored/cool 链路失效 | 链路机械通（u_cool 正确更新）但封顶只给 +0.10 蓝、亮度~100，cross 不到白阈值；cool0=baseline | **链路活着但不能产生白**（"打不白"的直接原因） |
| 核光透射 core | 关核后白反升 2.48%；核光是橙非白 | **排除为白源**（核心透缝贡献橙） |
| 脉冲时序 pulse | 闭合态关脉冲 0.57%（有贡献）；展开态间歇格仅 15/67，纯闪白格仅 2 | **次要调制（±0.3%），非主因** |
| 后处理过曝 / fx | 未单独 toggle（属上午消融范围）；core_off/pulse_off 反向变化不支持 HDR 过曝为主因 | **弱排除**（建议源码审计补 fx=0 对照） |
| alpha / 透明度 | cool alpha*=1.225 只增透不增亮；半透明晶体面在展开态暴露 | **参与可见度，非白亮度来源** |
| **晶体碎片基础面亮度（视角/fresnel/背面）** | 内片 stored=0 最白；rot45 白% 翻 3 倍；50/67 格持续白；shellInner/core/fac/cool 全关仍残留 ~1.4% | **展开态白的主因（待源码审计定位具体 shader 项）** |

## 8. 交源码审计子代理核对的疑点清单
1. **L1266 冷色项幅度过小**：u_cool 封顶 0.5 仅 +0.10 蓝、alpha×1.225，无法解释也无法产生"撞击变白"。核对是否曾有亮度项被删/压低（注释称"白块问题由 _STORED_DRAIN 根治"），用户预期的"击打应变白"与当前 shader 幅度不匹配。
2. **内片白来源**：band0/1/2 stored 恒 0（L2083 只指派 band3），但内片（#13/#8）是最白碎片。定位展开态下让内片基础面达亮度>150 的具体 shader 项（fresnel? 背面? u_deploy? L1233 alpha 公式）。
3. **L1233 alpha = clamp(0.42+0.30*fres+0.18*u_deploy, 0, 0.92)**：展开态 u_deploy→1 是否把内片 alpha 推到 0.92 使其半透明叠加变亮白。
4. **pulse_off 在 p=0.9 反使白升（1.60→2.13%）**：核对脉冲是否在"压暗"某些面，而非增亮。
5. **core_off 反使白升（1.60→2.48%）**：核对核心是否在做减法/遮挡，关掉后背面晶体面暴露。
6. 建议补 `fx=0`（后处理关）对照以最终排除/确认 HDR 后处理过曝（本次未单独 toggle）。
